## Remaining Phase-1 gaps (the "first-run polish" surface)

Verified in code on 2026-08-04:

1. **CLI suggestion rows hide the arg hint.** Rows render `trigger - title`
   (e.g. `note - Create New Note`) but never show `cmd.hint` (e.g. `[content]`).
   The hint only appears in the hint bar on exact match. New users can't see
   what a command *takes* from the dropdown.
2. **CLI suggestions have no footer hint bar.** QuickOpen's palette has
   `↑↓ navigate · ⏎ open · Esc close` + result count; the CLI dropdown has
   neither. After the tour, discoverability of `↑↓`/`⏎`/`⇥` reverts to tribal
   knowledge.
3. **Help modal has no keyboard-shortcuts section.** `OPERATOR MANUAL` lists
   commands only; the tour's shortcut list isn't echoed anywhere persistent.
4. **No way to replay the tour.** Once dismissed, `first_run` is false and the
   tour is gone (`help` doesn't mention it). No `tour` command exists.
5. **No mouse-friendly quick toolbar.** The dock launches *links*, not
   features. A first-time mouse user has no visible affordance for Notes,
   Kanban, Calendar, or Settings — keyboard-only discoverability.

## Proposed next sprint — "Discoverability & mouse parity"

### P0 — Quick-access toolbar (mouse parity)
- Optional micro-icon bar (Notes, Kanban, Calendar, Daily agenda, Pomodoro,
  Settings) that calls the existing managers (`Notes`, `KanbanManager`,
  `Calendar`, `DailyAgenda`, `Pomodoro`, `SettingsUI`).
- Config toggle `show_toolbar` (default on), hidden in zen mode.
- Mirrors the CLI — same actions, mouse path.

### P1 — Palette/CLI polish
- CLI suggestion rows: append the arg hint → `note - Create New Note [content]`
  (and bookmark rows keep `⏎ open`).
- CLI suggestions footer: `↑↓ navigate · ⏎ run · ⇥ fill · Esc close`
  (mirrors QuickOpen's footer).

### P2 — First-run polish
- `tour` command → re-runs `OnboardingTour.start()` (persist `first_run` flip
  only on completion, so replay stays available).
- Add the keyboard-shortcuts list to the help modal (shared `SHORTCUTS` table,
  currently defined in `OnboardingTour.js`).

### Deferred (tracked, not this sprint)
- GitHub contribution widget + dev-news feed (Phase 2).
- Auto-export/backup prompts; WebDAV/Gist sync bridges (Phase 2).
- ES-module/Vite build + theme/plugin API (Phase 3).

## Acceptance criteria
- Toolbar togglable in settings, zen-aware, keyboard shortcuts unchanged.
- CLI rows + footer make every command's args and key flow visible without
  running it.
- `help` and `tour` are bidirectional entry points for onboarding.
- `docs:check` clean, unit suite green, E2E green (CI-sharded).
